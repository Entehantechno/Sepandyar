# نقشه راه تبدیل «همراه من» به محصول نهایی

## تصمیم‌های این نسخه

- **پلتفرم فاز اول:** Android
- **مکالمه:** بدون دکمه، با شنیدن خودکار هنگام باز بودن اپ
- **مدل زبانی:** قابل تعویض؛ بدون قفل‌شدن روی یک ارائه‌دهنده
- **سلامت در فاز اول:** ورود دستی، OCR و ثبت تاریخچه
- **اتوماسیون کارها:** Android Accessibility Service برای اپ‌های منتخب، با تأیید صوتی نهایی

## مرحله صفر — اعتبارسنجی محصول | هفته ۱ تا ۲

### خروجی‌ها

- تست کاربردپذیری با ۸ تا ۱۲ سالمند واقعی
- تست جداگانه با ۵ تا ۸ فرزند یا مراقب
- تعریف ۲۰ سناریوی واقعی: دارو، تماس، خرید، غذا، فشار خون، بی‌خبری
- تعریف واژگان فارسی، لهجه‌ها و فرمان‌های جایگزین
- تعیین سطح توانایی بینایی، شنوایی، حرکتی و شناختی کاربران
- مشخص‌کردن محدوده حقوقی محصول: دستیار و wellness، نه تشخیص یا تجویز

### معیار قبولی

- سالمند بدون راهنمایی بتواند یک گفت‌وگو را شروع کند.

- بتواند یک درخواست خرید را تا مرحله تأیید نهایی پیش ببرد.
- در هر مرحله بداند اپ چه چیزی شنیده و چه کاری انجام می‌دهد.

## مرحله یک — هسته Android | هفته ۳ تا ۶

### تکنولوژی پیشنهادی

- Kotlin
- Jetpack Compose
- Android SpeechRecognizer یا موتور STT قابل تعویض
- Android TextToSpeech برای fallback
- Room برای ذخیره‌سازی محلی
- WorkManager برای یادآوری و بررسی دوره‌ای
- Hilt برای Dependency Injection
- DataStore برای تنظیمات
- BiometricPrompt برای بخش مراقب و اطلاعات حساس

### ساختار اپ

```text
app/
  core/
    audio/
    security/
    accessibility/
    notifications/
    database/
  feature_home/
  feature_conversation/
  feature_medications/
  feature_vitals/
  feature_food/
  feature_care_circle/
  feature_settings/
```

### تجربه شنیدن خودکار

1. با ورود به صفحه اصلی، وضعیت میکروفون نمایش داده می‌شود.
2. مجوز میکروفون با توضیح ساده و قابل شنیدن گرفته می‌شود.
3. VAD تشخیص می‌دهد سالمند شروع و پایان جمله را چه زمانی گفته است.
4. صوت به STT فارسی ارسال می‌شود.
5. متن شنیده‌شده روی صفحه نمایش داده می‌شود.
6. Intent Router تصمیم می‌گیرد پاسخ بدهد یا Workflow اجرا کند.
7. در زمان پخش پاسخ، میکروفون از صدای خروجی محافظت می‌شود.
8. پس از پایان پاسخ، شنیدن خودکار از سر گرفته می‌شود.
9. در خطا، اپ به‌صورت قابل فهم دلیل را اعلام می‌کند و به حالت آماده برمی‌گردد.

### الزامات فنی مهم

- توقف خودکار شنیدن هنگام تماس تلفنی، ضبط ویدئو یا خروج از صفحه
- نمایش نشانگر فعال بودن میکروفون
- عدم ذخیره فایل خام صوتی به‌صورت پیش‌فرض
- محدودیت زمانی برای هر نوبت شنیدن
- مدیریت قطع اینترنت
- جلوگیری از حلقه شنیدن صدای TTS
- بازگشت امن پس از crash یا kill شدن سرویس

## مرحله دو — Backend و لایه هوش مصنوعی | هفته ۵ تا ۸

### معماری مستقل از مدل

اپ مستقیماً به مدل زبانی وصل نمی‌شود. تمام درخواست‌ها از API Gateway عبور می‌کنند:

```text
Android App
   ↓ HTTPS
API Gateway
   ↓
Conversation Orchestrator
   ├── LLM Adapter
   ├── Intent Router
   ├── Tool Permission Engine
   ├── Medication Service
   ├── Vitals Service
   ├── Caregiver Service
   └── Audit Log
```

### Intentهای نسخه اول

- `conversation.general`
- `medication.list_today`
- `medication.confirm_taken`
- `medication.snooze`
- `vitals.add_manual`
- `vitals.parse_ocr`
- `food.analyze_photo`
- `commerce.search_item`
- `commerce.review_order`
- `commerce.confirm_order`
- `caregiver.call`
- `emergency.request_help`

### قانون مهم ابزارها

مدل به‌تنهایی نمی‌تواند ابزار پرخطر را اجرا کند. هر ابزار دارای این موارد است:

- سطح ریسک
- داده ورودی معتبر
- نیاز یا عدم نیاز به تأیید کاربر
- محدودیت زمانی
- قابلیت لغو
- لاگ قابل بررسی

پرداخت، سفارش نهایی، تغییر دارو، تماس اضطراری و اشتراک‌گذاری داده سلامت همیشه به تأیید جداگانه نیاز دارند.

### قرارداد پاسخ مدل

```json
{
  "intent": "commerce.review_order",
  "confidence": 0.94,
  "spoken_reply": "دو بسته شیر کم‌چرب...",
  "requires_confirmation": true,
  "tool_call": {
    "name": "review_order",
    "arguments": {}
  },
  "safety": "normal"
}
```

## مرحله چهار — Accessibility Automation | هفته ۹ تا ۱۳

### اصل طراحی

کنترل اسکرین فقط برای اپ‌های مشخص و سناریوهای محدود پیاده می‌شود؛ نه کنترل نامحدود همه اپ‌ها.

### روند خرید

1. تشخیص کالا و تعداد از گفتار
2. نمایش فهرست ساده
3. بازکردن فروشگاه منتخب
4. پیدا کردن کالا با UI یا Deep Link
5. اعلام قیمت و هزینه ارسال
6. توقف و گرفتن تأیید صوتی
7. اجرای پرداخت فقط پس از تأیید
8. ثبت نتیجه و رسید
9. قابلیت لغو تا حد امکان

### محافظ‌های Accessibility Service

- فهرست سفید اپ‌ها
- عدم خواندن رمز، OTP و اطلاعات کارت
- ماسک‌کردن فیلدهای حساس
- عدم اجرای کلیک کور
- توقف در صورت تغییر غیرمنتظره صفحه
- اسکرین‌شات فقط در حافظه موقت و با رضایت
- لاگ رویداد بدون ذخیره داده حساس
